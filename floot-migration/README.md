## Contents and reproduction

`app/` contains the authored Floot primitives. It is a platform source snapshot, not a standalone npm application. Provision Floot's `auth` resource (its standard auth components/endpoints, schema and database), install the dependencies below, run `schema.sql`, then write these paths to the same Floot project. Retain the seeded auth files not overridden here. The schema helper is regenerated by Floot. Set the existing server resource RECIPES_API_KEY; never embed it in client files. FLOOT_DATABASE_URL and JWT_SECRET are provided by auth provisioning. RECIPE_GITHUB_TOKEN already exists but the beta does not use it or publish to GitHub.

Dependencies added: cheerio 1.2.0, pdf-lib 1.17.1, @pdf-lib/fontkit 1.1.1, qrcode 1.5.4, ipaddr.js 2.5.0, @types/qrcode 1.5.6. Seed auth dependencies include jose, bcryptjs, superjson, postgres, kysely-postgres-js, kysely 0.26.3 and nanoid.

`assets.json` records 128 transferred assets and Floot storage URLs. These are project-specific. Assets were downloaded from the source commit and verified against Git blob SHA1 before upload. DejaVu Sans regular/bold were separately uploaded for PDF export; their URLs are in the Studio page. Uploaded original cards are unchanged.

Run `python3 floot-migration/build.py` to regenerate the legacy library document from the original source. The original 41 recipes are preserved in static/recipes.json. The wrapper retains browsing, filters, detail, favourites, shopping, meal planning and device settings. It adds explicit eight-key device backup/restore and approved-owner private recipes. It does not provide cold-start offline operation because Floot does not support the custom service worker.

`../migration-backup.html` is prepared for deployment on the OLD production origin. It has not been deployed. It exports that origin's eight localStorage keys for import on the new origin. A different origin cannot read them. Keep browser backups private.

## Studio behavior

Admin-only, per-user draft persistence; public self-registration grants no generation access. A verified owner account must be enabled before owner use. URL ingestion rejects private/reserved addresses and pins DNS; source facts, URL, hash and ingestion time are retained. Drafts use source nutrition only; adaptations or relevant edits invalidate it. Provider failures and unconfigured generation return errors, not placeholder success. Image generation was exercised against the real configured provider. Save uses stable BD-BETA UUID identities until production numbering can be handed over safely. Six-stage card export uses the existing brand and A4 landscape front/back. Overflows fail instead of clipping.

Restore is transactional and replay-safe for matching records; conflicting records fail. JSON backups currently reference private image storage and are not self-contained media disaster-recovery bundles. New recipes are private, not published to the shared 41-recipe corpus. Their PDFs are downloaded rather than persisted/indexed in the public repository. These are cutover blockers.

## Production gate and rollback

Do not switch DNS or stop either old service. Resolve offline requirement/platform incompatibility, public publishing and permanent ID ownership, complete media recovery, old-origin settings export, owner access, comprehensive device/print checks and archive exceptions first. Reconcile all old build/mirror archives before retirement. Then export database/media/device data, freeze writes, repeat count/hash checks, publish a Floot staging address, verify and obtain any outstanding production approval. Only then use Floot's domain wizard and record its exact DNS values. No speculative DNS records are supplied.

Rollback: retain Cloudflare Pages deployment/domain configuration, Railway service/environment, old repo commit and all source/archive files. Restore previous DNS if switched; unfreeze old publisher after checking writes made during cutover. Floot code checkpoints do NOT roll back database rows, assets or published deployments. Avoid destructive schema migrations; export data before any rollback.
